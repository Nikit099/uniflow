# User flow

Student: MAX `/start` → Mini App → language/onboarding → applicable procedure → case → next best action → checklist → upload demo documents → submit → receive correction → replace only that item → resubmit → university verification result.

Staff: queue → assign → inspect student context/source/document → accept or request changes with a reason → accept corrected item → confirm package reviewed by university.

Admin: verify sources → import or clone procedure draft → bind sources and localized content → validate declarative rules → activate → monitor internal aggregate metrics.

Unsupported profiles do not receive invented instructions. They see that staff review is required and can ask a question.
